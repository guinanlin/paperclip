# 创建 Issue 快捷方式 — 产品需求文档

**日期**: 2026-03-16  
**状态**: 需求草案  
**入口**: 新建 Issue 弹窗（New Issue Dialog）及后续可能的管理入口

---

## 1. 背景与问题

### 1.1 现状

- 在「新建 Issue」弹窗中，标题输入框上方有一组**固定文案**的快捷按钮（如：员工招聘、产品定义、需求评审、新需求开发、Bug 修复、文档编写）。
- 点击某一项会将该文案填入**标题**字段，仅此而已。
- 该列表来自前端常量 `QUICK_TITLE_TEMPLATES`，不可配置、不可扩展。

### 1.2 痛点

- **数量与类型受限**：不同团队/公司常用标题差异大，固定几条无法覆盖。
- **无法自定义**：用户不能按自己习惯添加、修改、删除快捷项。
- **仅作用于标题**：若希望快捷带入「描述」「状态」「优先级」甚至「默认项目」等，当前无法实现。
- **无分类**：快捷项增多后，平铺列表难以浏览和快速定位。

因此需要将「快捷输入」升级为**可持久化、可管理、可分类**的**快捷方式（Shortcuts）**能力，数据落库并按公司隔离。

---

## 2. 产品目标

- **让用户在创建 Issue 时能快速套用常用模板**，减少重复输入、统一用语。
- **快捷方式由用户自行维护**：支持增删改、可选分类，数据存入 DB，按公司隔离。
- **使用体验优先**：在新建 Issue 弹窗里便于发现、选择与筛选，同时提供便捷的管理入口（添加/编辑/分类）。

---

## 3. 概念定义

### 3.1 快捷方式（Shortcut）

一条「快捷方式」表示：**在创建 Issue 时可选的一则预设填充方案**。

- **最小形态**：仅包含**标题**（与当前行为一致，点击即填标题）。
- **扩展形态**：可包含若干字段的子集，例如：
  - 标题（必填）
  - 描述/正文（可选，支持多行或 Markdown）
  - 默认状态（如 backlog / todo）
  - 默认优先级（如 medium / high）
  - 默认项目（可选，company 下某 project）
  - 其他新建 Issue 表单上存在的字段，若产品需要也可纳入

产品上可先支持「标题 + 描述」，其余字段作为后续迭代。

### 3.2 分类（Category）

- **用途**：对快捷方式分组，便于在弹窗中折叠/展开或按 Tab 切换，避免一屏内过多按钮。
- **属性**：分类可有名称、可选排序（如显示顺序）、可选图标/颜色（可选，视 UI 需要）。
- **关系**：一条快捷方式**最多属于一个分类**；未归类的可视为「未分类」或「常用」。
- **是否必做**：首期可做「无分类 + 单列表」，分类作为增强项；或首期就支持分类，以便后续扩展。

## 4. 数据与范围

### 4.1 数据归属（与现有规范一致）

- **公司隔离**：所有快捷方式（及分类）均**按公司（company）维度**存储与展示，不与其它公司互通。
- **权限**：仅 Board（或当前有权限在对应公司下创建 Issue 的操作者）可管理快捷方式；使用快捷方式创建 Issue 时，权限与直接创建 Issue 一致。

### 4.2 数据落库

- **快捷方式**：持久化到 DB，建议新表（如 `issue_creation_shortcuts` 或 `issue_shortcuts`），字段至少包括：
  - id, companyId, 标题, 描述（可选）, 其它可填充字段（可选）
  - 分类 id（可选，若支持分类）
  - 排序/顺序、createdAt、updatedAt 等
- **分类**（若做）：建议新表（如 `issue_shortcut_categories`），字段至少包括：
  - id, companyId, 名称, 排序, createdAt, updatedAt

具体表结构在实现阶段再定，本文档只约定「存 DB、按 company 隔离」。

### 4.3 与「Agent 指令集」的关系

- **Agent 指令集**（见 `2026-03-16-agent-automation-requirements.md`）：按 **Agent** 维度，在 Automation 页「一键创建 Issue 并分配给该 Agent」。
- **本需求（创建 Issue 快捷方式）**：按 **Company** 维度，在**新建 Issue 弹窗**中「快速填充标题/描述等」，不绑定特定 Agent，分配等仍由用户在表单里操作。

二者场景不同，可独立实现。若未来希望「快捷方式」也能被某 Agent 的指令集引用（例如从模板库选一条作为指令内容），可在后续通过共享模板数据或 API 收敛，不在本需求首期范围。

## 5. 功能需求

### 5.1 使用侧（新建 Issue 弹窗）

| 项目 | 说明 |
|------|------|
| 展示位置 | 保持当前标题输入框上方区域，用于展示快捷方式（及可选分类）。 |
| 展示形式 | 首期可为「可点击的芯片/按钮」列表；若支持分类，可为「按分类分组的芯片」或「分类 Tab + 该分类下芯片」。 |
| 点击行为 | 点击一条快捷方式后，根据其配置**填充**表单对应字段（如标题、描述等），不自动提交；用户可再编辑后提交。 |
| 空状态 | 若该公司下无任何快捷方式，可隐藏该区域或展示「添加快捷方式」引导（跳转管理或内联添加）。 |
| 数量与性能 | 若快捷方式很多，可只展示前 N 条 +「更多」展开，或依赖分类折叠，避免一次渲染过多。 |

### 5.2 管理侧（添加 / 编辑 / 删除 / 分类）

| 项目 | 说明 |
|------|------|
| 添加入口 | 用户能「随时添加」：入口可放在新建 Issue 弹窗内（如「+ 添加快捷方式」），和/或设置/公司下的独立「快捷方式管理」页。 |
| 编辑与删除 | 支持对已有快捷方式编辑（标题、描述等）、删除；删除仅影响该条记录，不影响已创建的 Issue。 |
| 分类管理 | 若支持分类：支持创建/重命名/删除分类、调整顺序；支持将快捷方式归入某分类或移出分类。 |
| 顺序 | 快捷方式在列表中的顺序可支持拖拽或数字排序，便于把常用项排在前面。 |

### 5.3 非功能

- **权限与审计**：仅 Board（或同等权限）可管理快捷方式；若后续有「使用快捷方式创建 Issue」的审计需求，可记入 activity log（与普通创建 Issue 一致或单独事件，实现时再定）。
- **多端/多上下文**：同一公司下，不同入口（如 Board UI、后续可能的 API/移动端）看到的快捷方式列表一致，以 DB 为准。

## 6. 交互与体验设想（供讨论）

- **弹窗内添加快捷方式**：在「新建 Issue」弹窗中，用户填写好标题（和描述）后，可点「保存为快捷方式」，将当前内容存为一条新快捷方式（可选选择分类），下次即可在列表中点选。这样「用一次即沉淀」。
- **管理页集中管理**：公司设置或单独「快捷方式」页中，列表展示所有快捷方式（及分类），支持增删改、拖拽排序、归类，适合批量维护。
- **分类的展示**：若分类较多，可 Tab 切换；若分类少，可折叠面板或分组标题 + 芯片，避免占满整屏。
- **默认模板**：系统是否提供「公司创建时预置几条通用快捷方式」可选（如当前那 6 条），可作产品策略讨论；若提供，需支持用户编辑/删除。

## 7. 迭代建议

| 阶段 | 范围 |
|------|------|
| **首期** | 快捷方式仅包含「标题」+ 可选「描述」；数据落库、按公司隔离；新建 Issue 弹窗展示并支持点击填充；提供「添加/编辑/删除」的简单管理（弹窗内或单独页二选一或都做）。 |
| **后续** | 支持「分类」：分类 CRUD、快捷方式归属分类、弹窗按分类展示。 |
| **再后续** | 快捷方式支持更多默认字段（状态、优先级、默认项目等）；可选「从当前表单保存为快捷方式」；排序/拖拽；与 Agent 指令集联动（若需要）。 |

---

## 8. 开放问题（待产品/实现确认）

1. **首期是否必须支持分类？** 若首期只做平铺列表，实现更简单；若首期就做分类，体验更完整但工作量更大。
2. **管理入口优先级**：先做「弹窗内 + 设置页」双入口，还是先只做弹窗内「保存为快捷方式」+ 设置页列表管理？
3. **是否预置默认快捷方式**：新公司是否带 6 条默认项（可编辑/删除），还是完全空白由用户自建？
4. **描述字段的格式**：纯文本 vs Markdown，与新建 Issue 描述编辑器是否一致。

---

## 9. 总结

- **快捷方式**：创建 Issue 时的可复用填充模板，至少包含标题，可扩展描述等，**数据存 DB、按公司隔离**。
- **分类**：可选能力，用于分组展示与管理，便于用户随快捷方式增多时保持清晰。
- **使用**：在新建 Issue 弹窗中点击快捷方式填充表单，再编辑提交。
- **管理**：用户可随时添加、编辑、删除、排序（及归类），通过弹窗内入口和/或设置/管理页完成。

本文档仅描述产品需求与设想，不涉及具体接口与表结构实现；实现时需遵循 `AGENTS.md` 与 `doc/SPEC-implementation.md` 中的公司隔离、权限与审计等约定。
